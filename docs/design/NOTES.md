# ToiMatch — дизайн-эталон

Четыре самостоятельные HTML-страницы для переноса в Next.js + Tailwind v4. Данные взяты из `contractors.json`, названия полей ответа соответствуют `contract.ts`. Исходные BRIEF.md, contract.ts, contractors.json и фотографии не изменялись.

## Что готово

| Файл | Содержание |
| --- | --- |
| `index.html` | Каталог всех 66 профилей: фотографии, категории, город, формат, язык, минимальная и максимальная цена, сортировка по цене. Первые 12 карточек и последовательная загрузка остальных кнопкой. |
| `match.html` | Конструктор запроса, четыре примера в один клик, три исхода, критерии выбора, до трёх объяснённых карточек, причины исключения, сравнение дат, четыре шага работы сервиса. |
| `admin.html` | Вкладки «Подбор», «Каталог», «Качество». Таймлайн событий, воронка, имена и причины исключения, проверка утверждений, сравнение дат, JSON. Плотная таблица всех 66 профилей с поиском, флагами и занятостью. |
| `contractor.html?id=HK-44733` | Профиль по ID, крупная фотография, цена, описание, форматы, языки, часы, флаги и интерактивный календарь. Неизвестный ID получает отдельное понятное состояние. Без параметра открывается Буллма. |

Общая шапка и ссылки связывают все страницы. RU / ҚАЗ / EN переключаются сразу; выбор сохраняется между страницами, если браузер разрешает localStorage. При запрете хранилища страницы продолжают работать.

## Запуск и автономность

Можно открыть `index.html` непосредственно с диска. В каждой странице встроены все 66 исходных записей, CSS, JavaScript и SVG-иконки. Соседние HTML, `photos/{id}.webp` и `contractors.json` должны оставаться в этой папке.

При HTTP-открытии сначала запрашивается `contractors.json`. При недоступности данных или превышении 1,8 секунды используется встроенный снимок. При `file://` используется снимок без заведомо неработающего fetch. Google Fonts — единственный внешний ресурс; без сети используется запасной системный шрифт. Новые фотографии автоматически подхватываются по тем же ID. Отсутствующая фотография скрывается через `onerror`, под ней остаётся мягкий фон и SVG-иконка категории.

При необходимости локальный сервер запускается **из этой папки**:

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8765/index.html`. Сервер, запускавшийся при подготовке, остановлен.

## Визуальное решение

Основная идея — спокойный каталог людей и площадок, в котором доказательства становятся продолжением выбора. На первом экране каталога крупный заголовок и фотомозаика с Nerima Terrace. Карточки каталога лёгкие, без повторяющихся теней; карточки результата имеют белую поверхность, номер и отдельную область объяснения. Менеджер получает более плотный интерфейс с постоянной навигацией.

Расчёт контраста по формуле относительной яркости WCAG: основной текст на ivory — **11,09:1**; вторичный — **4,96:1**; тёмный текст на orange — **4,89:1**; teal на mint — **5,64:1**; amber на warm — **6,07:1**. Все десять проверенных текстовых сочетаний проходят AA 4,5:1. Белый текст на оранжевом не используется. Это проверка палитры, не сертификат доступности всего интерфейса.

### Типографика, сетка, компоненты

- Одно семейство: **Onest**, начертания 400–800, включая казахскую кириллицу. Системные шрифты только как запасной вариант при отсутствии Google Fonts.
- Токены шкалы: 12, 14, 16, 20, 24, 32, 44, 64 px. Основной текст интерфейса 13–15 px; подписи и плотная таблица меньше. Hero 43–64 px, заголовки разделов 27–36 px.
- Максимальная ширина контента 1280 px; боковые поля на широком экране 48 px, на планшете 32 px, на телефоне 18 px.
- Шкала отступов: 4, 8, 12, 16, 24, 32, 48, 72 px. Радиусы: 10, 16, 24, 32 px. Все значения вынесены в `:root` для переноса в Tailwind `@theme`.
- Каталог: три колонки на широких экранах, две на небольшом планшете, одна до 479 px. Карточки содержат фото, категорию, имя, цену, город, языки, флаги и ссылку в профиль.
- Подбор: одна поисковая форма, горизонтальная лента категорий, четыре основных поля; дополнительные категории, язык и часы по раскрытию. Результат: критерии, три карточки, раскрываемые причины исключения.
- Менеджер: боковая панель, компактный запрос, блоки таймлайна и воронки, таблица фактов, раскрываемый JSON. На телефоне навигация переходит в фиксированные нижние вкладки.
- Календарь: четыре месяца рядом на широком экране, два на планшете и одна колонка на узком телефоне. Сентябрь до 23-го недоступен. Занятые дни дополнительно зачёркнуты, а не обозначены только цветом.

## Поведение и состояния

### Подбор

Фильтры применяются последовательно: город, категория, дата, формат, бюджет, язык, длительность. Значение `max_hours: null` означает отсутствие ограничения в исходных данных. Ранжирование воспроизводимо. Для четырёх примеров сохранены заданные сценарии; для остальных запросов выполняется локальный детерминированный подбор по каталогу.

1. Ведущие, Алматы, корпоратив, 16.10, 1 000 000 ₸: **10 → 5 → 5 → 4 → 3**. Буллма, Куррапика, Хаул в заданном порядке. Занятые пять имён, Софи Хаттер и Мицури Канроджи объяснены отдельно.
2. Флористы, Алматы, свадьба, 15.10, 300 000 ₸: **2 карточки**, Тихиро Огино и Тони Тони Чоппер. Причина отсутствия третьей карточки написана явно; флаги синтетического профиля и проставленной цены видны.
3. Лайв-бэнд, Астана, свадьба, 14.11: **`no_category_in_city`**. Объяснение про пять групп в Алматы и действие для изменения города.
4. Декоратор, Алматы, той, 14.11, 3 000 000 ₸: **`all_filtered_out`**. Три занятых кандидата перечислены; также явно сказано, что ни один не оформляет той.

Имитация занимает около 1,5 секунды и показывает `criteria → filter_step → ranked → card → critic → done`. В менеджере код и моделируемые шаги ИИ различаются цветом и подписью. Тайминги и показатели качества отмечены как демо. Во время подбора поля и повторные действия формы отключены; итог объявляется через `aria-live`, фокус переводится в результат. Карточки появляются одной короткой последовательностью.

В JSON соблюдены `MatchResponse`, `MatchCard`, `CardFact`, `CardFlags`, `FunnelStep`. Список и детальная запись преобразуют snake_case исходного каталога в camelCase по контракту. В `window.ToiMatch` доступны `list(query)`, `detail(id)`, `match(request)`, `critic(response, request)`, последние события демонстрации и данные для проверки. Это локальные функции прототипа, не HTTP API.

Проверяемые слова в объяснениях подчёркнуты. Таблица связывает утверждения с `price_from_kzt`, `event_formats`, `languages`, `max_hours`, `description`. Самопрезентация имеет `verified: false` и подпись «Со слов подрядчика». Проверка означает соответствие **каталогу**, включая явно помеченные проставленные значения, а не независимое подтверждение реальных услуг.

### Даты и честность данных

- Календарь отображает точный включительный интервал **23.09–31.12.2026**, то есть **100 дней**. Процент занятости — число уникальных занятых дней внутри интервала / 100.
- Выбор даты показывает свободен / занят и переносит город, категорию, дату, формат и бюджет в форму подбора. Он не создаёт бронирование.
- Сравнение 16.10 / 23.10 показывает обязательные профили из задания. В исходном JSON 23 октября также свободна **Эмилия** (900 000 ₸), поэтому она явно указана дополнительным вариантом. Заданные три карточки 16 октября не менялись.
- В JSON у Тихиро Огино есть три формата: свадьба, юбилей **и той**. Профиль показывает все три исходных значения.
- Фраза Хаула «из четырёх свободных» относится к четырём кандидатам **в бюджете**; этот контекст дан в заголовке результата. До бюджетного фильтра свободны пять.
- У HK-64395 исходное анонимное имя — «Иноскэ Хашибира». Для витрины показано название **Nerima Terrace** из description; в профиле также сохранено исходное имя.
- На момент проверки присутствовало 30 `.webp`. В каждом фото или группе миниатюр есть пометка об ИИ-иллюстрации. Все остальные записи используют предусмотренную заглушку.

### Локализация и доступность

Все интерфейсные строки, справочники, подписи, календарь, состояния, кнопки и метрики имеют RU / ҚАЗ / EN в одном словаре. Имена, исходные описания и объяснения остаются на русском; для них указан `lang="ru"`, а в переведённом подборе есть пояснение. Содержимое контрактного JSON и технические имена событий/полей сохраняются без перевода.

Предусмотрены видимый фокус, ссылка пропуска шапки, семантические подписи полей, нативные кнопки и раскрытия, `aria-pressed`, `aria-expanded`, `aria-selected`, `aria-busy`, `aria-live`, заголовки таблиц и alt-тексты. Вкладки менеджера поддерживают стрелки, Home и End. `prefers-reduced-motion` выключает анимацию и плавное перемещение. Таблицы прокручиваются внутри своего контейнера; лента категорий — внутри своей области.

## Проверки и их границы

Выполнены:

- `node --check .work/troyka.js` — проверка синтаксиса JavaScript.
- `node .qa/verify.cjs` — **25 проверок** исходного кода и функций в Node VM: все четыре сценария, точные ID и порядок, воронка и причины, контрактные ключи, флаги, фильтры, цены, реальные даты, ошибки фактов, неизвестный профиль, 100 активных дат, полнота словаря, автономность четырёх HTML.
- В этом наборе перебраны **612 запросов**: 3 города × 17 категорий × 6 форматов × 2 даты. Проверены допустимость карточек, ограничение до трёх, повторяемость, непустые объяснения исхода и монотонность воронки.
- `python .qa/check_markup.py` — **39 фрагментов разметки** в трёх языках: уникальные ID, **111 внутренних ссылок**, существующие ID профилей, подписи полей, alt и onerror у изображений, заголовки таблиц. Рассчитан контраст десяти текстовых сочетаний.
- Результаты сохранены в `.qa/report.json` и `.qa/markup-report.json`. Эти проверки не запускают браузер и не обращаются в сеть.

**Ограничение:** автоматическая проверка доступа отклонила открытие `http://127.0.0.1:8765/index.html` в Chrome, сообщив, что доступ к адресу не разрешён. Альтернативные способы открытия в браузере не применялись. Скриншоты, фактический рендер на 360/375/768/1024/1440 px, работа нативного date picker и интерактивная проверка клавиатуры в браузере не выполнены. Нельзя считать локальные проверки полноценной визуальной приёмкой.

Это статичный прототип: реального LLM, SSE-сервера, рабочего кеша, авторизации, отправки сообщений или бронирований нет. Проценты и латентность раздела «Качество» — явно помеченные демонстрационные значения; состав каталога рядом вычисляется из настоящего JSON.

## Обновление эталонов

Новые исходники находятся в `.work/troyka.css`, `.work/troyka.js`, `.work/site_build.py`. Существовавшие `.work/build.py` и `.work/common.css` не заменялись. Сборка не требует npm или внешних пакетов:

```powershell
python .work/site_build.py
node .qa/verify.cjs
python .qa/check_markup.py
```

Последняя проверка использует BeautifulSoup, доступный в текущем окружении. Сгенерированные HTML от `.work` и `.qa` не зависят: эти папки нужны только для поддержания эталона и повторной проверки.
