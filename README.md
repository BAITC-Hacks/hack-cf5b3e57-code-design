# ToiMatch — умный подбор event-подрядчиков

HackAlem AI 2026 · трек 06 «Креативные индустрии» · задача Firebird #79-lite · команда Code & Design.

Заказчик задаёт город, дату, формат мероприятия, категорию и бюджет. Сервис возвращает до трёх подрядчиков с отдельным объяснением выбора каждого. Если подходящих меньше трёх или нет вовсе, он показывает причину, а не заполняет выдачу неподходящими профилями.

## Запуск из чистого клона

Нужны Docker с Compose и свободные порты 3000, 3001, 5433. Ключ модели не нужен: по умолчанию включён детерминированный режим `MOCK=1` без внешних LLM-вызовов. Первый `docker compose up --build` скачивает базовые образы и npm-зависимости; после сборки сам сценарий подбора работает без доступа к модельному API.

```bash
git clone https://github.com/BAITC-Hacks/hack-cf5b3e57-code-design.git
cd hack-cf5b3e57-code-design
docker compose up --build
```

Compose поднимает PostgreSQL, дожидается его готовности, применяет миграции, идемпотентно загружает 66 подрядчиков из CSV, запускает API и только после его готовности — фронтенд. База хранится в Docker volume; повторный запуск seed не создаёт дубликатов.

Откройте [http://localhost:3000](http://localhost:3000) — каталог, [подбор](http://localhost:3000/match), [рабочее место менеджера](http://localhost:3000/manager) или [чат](http://localhost:3000/chat). API: [http://localhost:3001/api/v1/health](http://localhost:3001/api/v1/health). `/admin` перенаправляет на `/manager`.

Во втором терминале проверьте весь основной сценарий (нужен Node.js 22+):

```bash
node scripts/smoke.mjs
```

Скрипт проверяет доступность фронта и API, 66 записей, плотную и редкую категории, два вида пустого результата, изменение выдачи при смене даты и повторяемость порядка и объяснений. Для просмотра числа записей напрямую:

```bash
docker exec hackaton-postgres psql -U postgres -d hackaton -c 'select count(*) from contractors;'
```

Ожидаемый `count` — `66`. Остановка без удаления данных: `docker compose down`.

## Демонстрация для жюри

На `/match` есть готовые примеры. Их можно также ввести вручную:

| Сценарий | Параметры | Что должно быть видно |
|---|---|---|
| Плотная категория | Алматы · 16.10.2026 · корпоратив · Ведущий · до 1 000 000 ₸ | Три карточки, индивидуальные причины выбора и воронка отсева |
| Другая дата | Те же параметры · 23.10.2026 | Другая тройка из-за занятости первой |
| Редкая категория | Алматы · 15.10.2026 · свадьба · Флорист · до 300 000 ₸ | Только две карточки и объяснение, почему их меньше трёх |
| Категории нет в городе | Астана · 14.11.2026 · свадьба · Лайв-бэнд · до 1 500 000 ₸ | `no_category_in_city`, понятное сообщение без карточек |
| Все отсеяны | Алматы · 14.11.2026 · той · Декоратор · до 3 000 000 ₸ | `all_filtered_out`, причина отсева без подмены категории |

На `/manager` тот же подбор показан как SSE-таймлайн: критерии, фильтрация, ранжирование, карточки, проверка и итог. Дату можно сравнить рядом, не теряя исходный запрос.

## Как устроен подбор

1. Код фильтрует каталог по городу, категории, занятости на дату, формату, бюджету и, если заданы, языку и длительности. На каждом шаге остаётся счётчик и причина отсева.
2. Код детерминированно ранжирует выживших; одинаковый запрос сохраняет порядок. В выдачу попадают максимум три профиля.
3. Для каждой карточки сервер строит варианты объяснения из данных профиля и параметров заказа. Модель может выбрать наиболее убедительный вариант, но не может вписать непроверенное утверждение. Метки фактов различают поля каталога и сведения из описания подрядчика. Проверенный текст повторного запроса кэшируется.
4. Ответ содержит один из трёх исходов: `found`, `no_category_in_city`, `all_filtered_out`. При малом или пустом результате `summary` объясняет ситуацию словами.

Бизнес-решение о допуске и порядке кандидатов принимает код, не языковая модель. Модель выбирает из фактических вариантов первого предложения, а сервер добавляет дату и цену из каталога; в режиме `MOCK=1` выбор полностью детерминирован. Данные — 66 анонимизированных профилей организаторов; синтетические профили и проставленные при подготовке датасета город/цена помечены в карточках. Изображения подрядчиков являются ИИ-иллюстрациями, не фотографиями реальных людей.

## Стек и структура

- `front/` — Next.js 16, React 19, TypeScript, Tailwind CSS; каталог, подбор, чат, рабочее место менеджера.
- `back/` — NestJS 11, Prisma 6; REST API `/api/v1/*`, SSE и логика подбора.
- `shared/contract.ts` — единый контракт запросов, ответов и событий.
- `back/prisma/` — схема, миграции, исходный CSV и идемпотентный seed.
- `docker-compose.yml` — PostgreSQL 16, backend и frontend.

Основные эндпоинты: `GET /api/v1/health`, `GET /api/v1/contractors`, `GET /api/v1/contractors/:id`, `POST /api/v1/match`, `GET /api/v1/match/stream`; чат — `/api/v1/chat/*`.

## Настройка и локальная разработка

Для демо ничего настраивать не требуется. Compose задаёт `DATABASE_URL` внутри сети контейнеров и `MOCK=1`. Ключи не хранятся в репозитории. Для включения живой модели установите `MOCK=0` и `OPENAI_API_KEY` в окружении перед запуском Compose. Если ключа нет, backend сам использует шаблоны. `MODEL_MAIN` по умолчанию — `gpt-4o-mini`.

Фронтенд обращается к API по двум адресам: серверные запросы — через внутренний `BACKEND_URL=http://backend:3001`, браузерный SSE — через публичный `NEXT_PUBLIC_API_URL=http://localhost:3001`, который встраивается на этапе сборки. При запуске не на localhost задайте публичный URL перед `docker compose up --build` и добавьте origin фронтенда в `CORS_ORIGIN`.

Для разработки без контейнеризации приложений сначала запустите базу `docker compose up -d postgres`, затем используйте инструкции в `back/AGENTS.md` и `front/AGENTS.md` с примерами из `back/.env.example` и `front/.env.example`.

Перед показом проверяйте сборку: в `back/` — `npm run build`, в `front/` — `npm run build -- --webpack`. В Docker фронт собирается тем же проверенным способом; сборка Turbopack в некоторых средах может надолго остановиться на этапе оптимизации.

## Ограничения

Это подбор, а не система бронирования: оплаты, заявок, авторизации и уведомлений нет. Маленький каталог честно возвращает меньше трёх вариантов в редких категориях. Режим с живой моделью требует сети и может быть медленнее демо-режима; критичный сценарий жюри проверяйте в `MOCK=1`.

Готовые библиотеки: Next.js, React, Tailwind CSS, NestJS, Prisma, PostgreSQL и Onest. Датасет предоставлен организаторами; для визуалов использованы ИИ-инструменты. Проект разработан с помощью Claude Code и OpenAI Codex.
