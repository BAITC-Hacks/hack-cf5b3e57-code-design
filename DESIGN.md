Утверждённые решения по визуалу и UX. Задача и механика — в [SCOPE.md](SCOPE.md), данные для экранов — строго из [shared/contract.ts](shared/contract.ts), тексты объяснений и итоговых фраз — в [docs/copy-explanations.md](docs/copy-explanations.md). ## Продукт в одной фразе
Заказчик выбирает, кто нужен, город, дату, событие и бюджет — сайт показывает, на что смотреть, до трёх подрядчиков и доказывает каждое слово объяснения фактами из каталога.

## Бренд
- **Название: ToiMatch** — «той» + «match», одинаково на RU / ҚАЗ / EN.
- **Логотип:** буква T с галочкой (оранжевая) + слово ToiMatch. Файлы в `front/public/brand/`:
  - `toimatch-logo.svg` — основной, на светлом фоне;
  - `toimatch-logo-light.svg` — для тёмного подвала;
  - `toimatch-mark.svg` — значок, он же фавикон (`front/app/icon.svg`).
- **Маскот: Нурлан** — консьерж в оранжевом жилете с гарнитурой. Позы в `front/public/mascot/`: `nurlan-hello`, `nurlan-thinking`, `nurlan-found`, `nurlan-sorry` (webp, прозрачный фон) и петля `nurlan-hello.mp4|webm` (5 с, фон `#FDF6EC`, показывать в скруглённом окне). Реплики маскота берутся из полей ответа: `criteria[0]` при найденном результате, `summary` при пустом. При `prefers-reduced-motion` — статичная поза.
- Все сгенерированные изображения (фото, маскот, логотип) указаны в README → «Что взяли готовым».

## Шрифт
**Onest** (Google Fonts), одно семейство на всё; поддерживает казахскую кириллицу (Ә Ғ Қ Ң Ө Ұ Ү Һ І). В Next: `next/font/google`, `subsets: ["cyrillic", "cyrillic-ext", "latin"]`.

## Языки
Интерфейс на трёх языках: **RU / ҚАЗ / EN**, переключатель в шапке. Для текстов модели нужен `locale` в запросе (в `shared/contract.ts` есть; в валидации бэкенда — пока нет). Вёрстка выдерживает длинные казахские слова: без фиксированной ширины кнопок, перенос в заголовках разрешён.

## Страницы
| Маршрут | Что |
|---|---|
| `/` | Каталог 66 подрядчиков: hero, CTA «Подобрать с ИИ», чипы категорий, фильтры, сетка карточек с фото |
| `/match` | Поиск-конструктор (чипы «Кто нужен?» + город / дата / событие / бюджет), 4 демо-запроса, результат: исход, «на что смотреть», до 3 карточек, кто не вошёл и почему, сравнение с другой датой, Нурлан |

## Принципы
1. **Объяснение важнее карточки.** Текст «почему» — главный текст карточки после имени.
2. **Доказательство в тексте.** Проверенные факты (`factsUsed[].verified = true`) подсвечены в объяснении по совпадению `label` с текстом; если совпадения нет — строкой под текстом. Слова подрядчика о себе — нейтрально, «со слов подрядчика».
3. **Честные исходы.** `found` / `no_category_in_city` / `all_filtered_out` различаются заголовком, иконкой и цветом; пустой результат — всегда словами.
4. **Сравнимость.** Строки критериев идут в одном порядке во всех карточках запроса.
5. **Клиповое внимание.** Одно главное действие на экран, короткие фразы, крупные фото, подробности по раскрытию, одна оркестрованная анимация появления результата.
6. **Работа ИИ видна.** Пока идёт подбор — шаги пайплайна из SSE, а не спиннер.
7. **Фото подрядчиков** — `front/public/contractors/{id}.webp`, сгенерированы ИИ (люди вымышленные), на каждом пометка «Фото: ИИ-иллюстрация»; нет файла — заглушка с иконкой категории.

## Доступность и адаптив
Контраст текста ≥ 4.5:1, видимый фокус, `prefers-reduced-motion`, `aria-live` для результата, иконки SVG, зона нажатия ≥ 44px. Проверено на 375 / 768 / 1280 / 1440 px, без горизонтального скролла на 360px; карточки подбора 1 / 2 / 3 колонки.
