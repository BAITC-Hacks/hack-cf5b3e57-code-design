# Orchestration playbook — Claude + Codex

Claude оркестрирует, Codex исполняет. Файл читается перед любой работой с Codex.

## Роли

| Claude | Codex |
|---|---|
| архитектура и решения | чтение / запись файлов |
| декомпозиция задач | поиск по кодовой базе |
| ревью diff'ов | запуск тестов, миграций |
| интеграция и коммиты | генерация данных / fallback |
| разрешение конфликтов | рутинная реализация по брифу |

Правило: если операция много читает или много пишет — Codex. Если решает — Claude.

## Экономия контекста Claude

1. Никогда не читать файл целиком «посмотреть» — просить Codex вернуть 3–5 конкретных фактов.
2. Ревью по `git diff` / `git diff --stat`, не по полным файлам.
3. Codex обязан возвращать краткий отчёт (формат ниже). Полный лог — в `/tmp/codex-last.txt` через `-o`, читать только при FAIL.
4. Не переспрашивать структуру проекта — она в корневом `AGENTS.md` (Codex его читает автоматически).

## Инвокация Codex

```bash
codex exec --approve-for-me --skip-git-repo-check -o /tmp/codex-last.txt "<бриф>"
```

Флаги по ситуации:
- `--json` — когда нужен машинный лог.
- `-C <dir>` — работа только в подпапке (front / back).
- `--worktree` — большая независимая фича в отдельном worktree.
- `run_in_background: true` в Bash — для параллельного запуска.

## Формат брифа

```
Задача: <одно предложение>
Файлы, менять можно: <точный список>
Файлы, НЕ трогать: остальное
Готово когда:
  - <проверяемый признак 1, с командой>
  - <проверяемый признак 2>
Проверь сам, покажи вывод команд.

Верни в конце ровно так:
FILES: <список изменённых файлов>
SUMMARY: <одна строка>
VERIFY: <PASS|FAIL + одна строка>
```

## Параллелизм

- 1 задача → синхронный `codex exec`.
- 2–3 не пересекающиеся по файлам → каждая в `run_in_background: true`, свой `-o /tmp/codex-N.txt`.
- Пересекающиеся файлы — только последовательно, иначе merge conflict.
- Крупная фича → `--worktree`, потом мерж.

## Что НЕ делегируем Codex

- Выбор архитектуры / библиотек / названий модулей.
- Правки в `AGENTS.md`, `SCOPE.md`, `README.md` (там смысл, а не механика).
- Коммиты в `main`.
- Работу с секретами и `.env` (только Claude, только с подтверждения человека).
